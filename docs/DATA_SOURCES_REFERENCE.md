## Full Source List with Verification Steps

### 1. RTFH WeAllCount Point-in-Time Count
- **What**: Annual countywide unsheltered/sheltered count
- **Data as of**: January 2026
- **Last verified**: August 2026
- **Status**: Public
- **How to verify**: 
  - Visit https://www.rtfhsd.org
  - Look for "PIT Count" or "Point-in-Time Count" press release
  - Confirm: 9,803 people counted in 2026
- **In app**: Countywide trend chart + KPI
- **Frequency**: Updated annually (January)

### 2. RTFH Monthly Data & Performance Reports
- **What**: Rolling 12-month inflow/outflow tracking by program
- **Data as of**: Rolling 12-month average, as of mid-2026
- **Last verified**: August 2026
- **Status**: Public
- **How to verify**:
  - Visit https://www.rtfhsd.org → Data & Reports
  - Look for monthly dashboard or performance report
  - Should show year-over-year metrics
- **In app**: Referenced in Forecast page for YoY trends
- **Frequency**: Updated monthly

### 3. RTFH Project-Level HMIS Dashboard (Aggregate)
- **What**: Aggregate HMIS data by program type (shelter, transitional, permanent)
- **Data as of**: October 2021 – December 2024 (historical snapshot available)
- **Last verified**: August 2026
- **Status**: Public (aggregate only; individual records protected)
- **How to verify**:
  - Visit https://www.rtfhsd.org → HMIS Dashboard
  - Should show program-level performance
  - Verify data end-date is current
- **In app**: Referenced for subgroup performance trends
- **Frequency**: Updated quarterly

## Verification Checklist (Monthly)

Use this to keep data current:

### Week 1 of each month (high-priority sources)
- [ ] RTFH monthly dashboard: Any new data published?
- [ ] San Diego County Homelessness Dashboard: Any updates?
- [ ] 211 San Diego: Any new reports or data?
- [ ] California EDD: Latest unemployment figures available?

### Month 1 of each quarter (medium-priority sources)
- [ ] accountability.ca.gov: New HHAP/ERF data available?
- [ ] Downtown San Diego Partnership: New monthly count?
- [ ] CA Housing Partnership: Any new reports?

### Once per year (annual/infrequent sources)
- [ ] RTFH PIT Count: Published (January)
- [ ] Census Bureau ACS: Updated (March)
- [ ] State Auditor reports: Any new audits on homelessness?

### When disputed (any metric users question)
- [ ] Go to the source directly
- [ ] Confirm the date range
- [ ] Confirm the methodology
- [ ] Document any discrepancies and update the note in `radarData.ts`

## What to Do When Data Changes

### If a source is updated and the number changes:
1. Update the value in `src/shared/data/radarData.ts`
2. Update the `dataAsOf` date in the `dataSources` array
3. Update the `lastVerified` date to today
4. Test the app locally to ensure UI updates correctly
5. Document the change in a commit message: "data: update [metric] from [source], verified [date]"
6. Consider adding a note if the change is significant (e.g., "Note: this month shows a larger increase than usual")

### If a source becomes stale (>6 months old):
1. Check if a newer data release is expected
2. If yes, mark it "Pending [expected release date]" in the Sources page
3. If no, check with the data owner (RTFH, County, etc.) to understand why
4. Consider adding a caveat: "Data as of [date]; newer release not yet published"

### If a source is no longer available:
1. Try to find a replacement or successor dataset
2. Contact the data owner to ask about archival/replacement
3. If no replacement exists, mark as "Historical data; not updated since [date]"
4. Consider removing from the dashboard if the gap is critical

## Notes for Judges / Demo Day

**When asked "where did you get this data?":**
- Point to the Sources page in the app
- Offer to verify any number on the spot by checking the source directly
- Emphasize: "Every number has a date and a named source. If you want to audit it, here's how."

**When asked "how current is this?"**
- Say: "Updated through [month/date]. See the 'Verified' date next to each source."
- Explain the monthly/quarterly/annual update cycles
- Offer to show how the verification checklist works

**When asked "what if this number is wrong?"**
- Say: "Then the source is wrong. Our app is only as good as our sources. That's why we list them explicitly — so you can check them independently."
- Offer to walk through the verification process for that source
